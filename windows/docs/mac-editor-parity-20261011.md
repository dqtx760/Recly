# Recly 剪辑能力对照与移植方案

核查日期：2026-10-11。范围：原作者演示、原版源码与当前 Windows 工作树。本轮交付为审查和实施方案，没有新增剪辑功能或重新打包。

## 结论

原作者演示的大部分剪辑能力可以在 Windows 实现。当前差距主要来自功能移植未完成：一部分已有算法与绘制代码却没有操作入口；另一部分只有模型或局部绘制函数，缺少素材加载、时间线求值或图层合成。

不能把这些模块全部当成“隐藏功能”，直接加按钮就发布。特别是贴图、连续 3D 运动和动态背景，需要完成预览、导出、项目保存与撤销的完整链路。

## 具体代码缺口

### 1. 时间线与编辑状态

- Windows 仅装配屏幕与缩放两轨：`windows/src/renderer/editor/app.js:34`、`app.js:93`、`editor.html`。
- `windows/src/core/timeline.js:82` 已有重排逻辑；`timeline-view.js:137` 的主片段拖动未接入重排。
- `windows/src/renderer/editor/waveform.js` 已能提取与绘制波形，需要在片段内按源区间、音轨 offset 和变速正确截取峰值。
- `windows/src/renderer/editor/store.js:13` 的选择状态与 `restore()` 只区分主片段和缩放。增加效果轨后，撤销、删除、选中检查器都要识别各自片段集合。
- 原版参考：`Sources/RecorderCore/ProjectTimelineEditing.swift:465`、`:529`，`Sources/DogSCApp/EditorTimelinePrimaryEditing.swift`、`EditorTimelineMagneticSnap.swift`。

### 2. 开场、裁切、外框、摄像运动

- 共享场景已有裁切、开场、样机和摄像运动调用：`windows/src/core/scene.js:25`、`:269`、`:310`、`:359`。
- 检查器没有这些新增入口：`windows/src/renderer/editor/inspector.js:138`、`:269`。
- 摄像画面在 `render.js:678` 仅居中铺满，缺蒙版内独立取景。
- 原版参考：`ProjectModel.swift:177`、`CameraMotion.swift`、`CameraContentFill.swift`、`MotionInspectorViews.swift`。

### 3. 贴图与遮挡

- `windows/src/renderer/editor/render.js:220` 的 `prepare()` 只加载背景图。`:757` 期望贴图图像，但预览 `preview.js:265` 与导出 `export.js:123` 没有提供贴图位图。
- 固定绘制顺序在 `render.js:779`，尚未执行贴图的 `hidesScreen`、`hidesCamera` 语义。“仅背景”不能靠保存一个标志完成。
- 视频展示的是相邻贴图片段之间的位置/尺寸接续，优先参考 `Sources/RecorderCore/StickerTransition.swift`；无需为了复现演示先做通用关键帧编辑器。
- 区域柔化绘制在 `render.js:336`。目前区域直接乘目标矩形，柔化又按未裁切源帧重画；开启源画面裁切后应先修正这条映射，再开放遮挡入口，防止遮住了错误位置。
- 素材导入或粘贴后应复制到工程媒体目录，以项目相对路径引用；删除原外部图片后工程仍能重开和导出。

### 4. 连续 3D 与动态背景

- `windows/src/core/scene.js:324` 只读取静态 XYZ 旋转和透视，没有读取屏幕运动片段。参考原版 `ScreenMotion.swift` 的目标状态采样及前后片段继承。
- 聚焦虚化已有独立 `focus.js`，不能把其单元测试通过视作完整 3D 焦点效果已接入。
- `render.js:225` 的背景缓存不包含时间，预览与导出也未提供视频背景帧。需要区分静态缓存、动态程序图案与视频解码输入。
- 3D 当前使用 Canvas 网格投影，4K、多个柔化和多个图层叠加后的实时性能需要实测；不能保证直接达到原版演示的流畅度。

## 建议实施顺序与验收

### 第一批：基础剪辑闭环

Q/W 波纹裁切、拖动重排、波形显示、缺口恢复、吸附与片段音量。

验收：用同一段带语音素材剪切、重排、变速和恢复；麦克风、系统音、摄像头与光标仍对应同一源片段。预览与导出接点一致，撤销/重做和重开项目不丢操作。分割后的两个片段继承音量覆盖。

### 第二批：实用画面编辑

源画面裁切、样机外框、图片导入/粘贴、柔化/聚光叠加轨、仅背景显示、效果复制与粘贴属性。

验收：将源画面的四角和敏感区域作标记，叠加裁切与缩放后检查遮挡位置；多个贴图正常显示且保存为工程内素材；同一帧预览与导出一致，移动工程后仍能加载。

### 第三批：动画与性能

开场设置、连续屏幕 3D、摄像运动与蒙版内取景、相邻贴图接续。动态网格可先做，视频背景随后接入；同时补用户可选择的预览质量及窗口隐藏时的暂停策略。

验收：在片段开始、过渡中点、衔接点和结束逐点比较输出；剪掉原素材开头后，开场仍按约定在成片开头执行。组合 3D、遮挡、摄像和贴图，实际测量预览响应与导出耗时。

## 时间与渲染约定

Windows 当前由输出时间映射到源时间，再给预览和导出的共享 `evaluateScene()` 求值。新增功能必须明确时钟：点击/光标等与源录制对应的效果随素材；开场从成片开头计时；用户添加的叠加片段需明确重排后的跟随规则；背景视频也应约定循环相位。不能把原版效果时点不经转换直接写入当前模型。

继续让预览与导出调用同一场景求值与合成器。新增 UI、片段模型、素材加载、保存迁移、撤销、预览、导出缺一项，都不能算产品功能完成。

## 字幕与语音跟随提词器

当前原版项目契约 `Sources/RecorderCore/ProjectModel.swift:3` 明确不保留旧字幕模型；本次演示没有展示字幕编辑或按语音自动滚动。视频成片中的字幕不能证明字幕由该编辑器生成。

这两项能作为 Recly 的新增能力，但需要独立开发。字幕可先做手动字幕/SRT 导入和共享绘制，再接自动识别；语音跟随提词器需要实时识别与文稿位置匹配，仅检测有人说话后滚动不能算真正跟随文稿。
